Subagent Live Output 内联卡设计

Tact TUI · 组件一：嵌在日志流里的运行中卡片 · 与「弹窗」分开设计（弹窗见同目录另一份）

定位：Live Output 是日志流里的一个内联组件——被动跟随、卡内预览、是通往弹窗的入口。 它不是一个阅读器：不承担滚动/选择/拷贝，这些是弹窗的交互。生命周期状态（运行中 / 完成 / 失败）的 胶囊在卡上展示；弹窗是常驻实时流视图（打开后一直保持，任何阶段双击都能打开）。本页只定义这张卡。

02 交互规格（只有卡自己的交互）

这张卡的交互集合刻意保持最小——它是「入口 + 状态」，不是「阅读器」。

交互行为
鼠标进入边框高亮为紫色 + 外发光（示意"可点"），光标变手型
单击记录点击位置（用于区分双击）；清除日志选区，便于用户双击
双击打开全量弹窗（open_subagent_popup(phys_idx)）——唯一的卡片级入口动作；任意阶段都可用（运行中=实时流，结束后=完整转录）
跟随刷新stream 到达时正文原地刷新（不走滚动条），卡始终显示最新 8 行
不可用操作卡内不提供：滚动、文本选择、拷贝（这些都在弹窗）
失败态卡头胶囊变 ✗ 失败，正文展示错误摘要而非 tail
完成态胶囊变 ✓ 完成，正文收缩为最终摘要 1-3 行

03 性能预算

卡的预览上限只有 8 行，瓶颈不在渲染而在于每 chunk 重建： on_tool_progress 目前每个 ToolProgress 都会重跑 ToolWidget::build()（重新计算行数 + 预览 + 布局），子代理高频输出时会放大为每帧 N 次重建。

成本点设计对策
① 每 chunk 全卡重建预览数据从 live_output.preview_lines(8) 直接取， 不再每次重建 ToolWidget；仅当 可见行数（1→3→8 阶梯）或元数据（token/耗时）变化时才重算卡结构
② 逐 chunk 触发多个 chunk 在同一帧内合并刷新：卡只反映帧末快照，不打乱行数渐进阶梯
③ token / 行数统计统计值走 ToolOutputBuffer::logical_line_count() 等 O(1) 计数，不遍历历史行

预算：子代理高频输出下卡更新成本 < 0.5ms/帧；预览剪贴始终只读 tail 8 行，与总行数无关。

04 键盘可达性

  • 卡本身不抢任何按键；运行中的卡在日志里可通过已有工具行聚焦逻辑定位（复用而非新造）。
  • Enter（在已聚焦的工具行上）等效双击：打开弹窗；运行中与结束后均可。
  • 不引入新的全局快捷键——Live Output 的"交互"就是看 + 点开。

05 数据与影响面

  • 数据源不变：ActiveToolBlock.live_output（ToolOutputBuffer）tail 预览。
  • 若 stream 分段化（见弹窗设计 05 节），预览行也带角色标记——只改 widgets/tool_widget.rs 的 Subagent 预览分支，数据层复用。
  • 涉及文件：widgets/tool_widget.rs（预览样式）、components/tool.rs（行数渐进 + 每帧合并重建）、handlers/mouse.rs（双击入口已有）。
  • i18n：i18n.rs 的 tool_live_output_title / tool_live_output_bottom 文案随新视觉微调。
