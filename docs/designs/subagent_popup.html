Subagent 弹窗设计

Tact TUI · 组件二：模态全量转录阅读器 · 与「Live Output 内联卡」分开设计（见同目录另一份）

定位：弹窗是常驻的模态实时流观察窗——打开后一直保持，直到用户 Esc / ✕ 主动关闭。内容是实时流：thinking / 工具块随 stream 增长、收束。没有"完成 / 失败 / 启动中"状态页——子代理结束只是流停止增长， 弹窗保持原位展示完整转录。正文参照主日志区块模型：thinking / tool 各为固定卡片块，普通文本线性排布。 由内联卡双击打开（任何阶段都可以），Esc 关闭。

01 视觉规格（实时流 · 常驻）

弹窗没有"完成 / 失败 / 启动中"之分：它是一个持续的实时流视图。头部常驻 ● Live 徽章（运行中脉冲）；子代理结束时流停止增长、光标消失，但弹窗保持打开，内容就是 完整转录——不再切换到任何状态页。

03 性能预算（弹窗渲染热路径）

弹窗是长驻实时流，且每帧都在跑（prepare_subagent_popup + render_subagent_popup 各一遍）。性能目标：长子代理（万行级转录）也不掉帧。 关键事实：live 状态下 content_len 每帧都在涨 → 现有指纹缓存几乎恒失效， 每帧全量重排整份转录——这是必须消除的第一位成本；其次是 render 阶段每帧的固定账本。

阶段成本点现状设计对策（含预算值）
prepare
（每帧）		 ① 恒失效 → 全量重排 live 时每帧 content_len 变大，is_valid 恒 false → 每帧 layout_all_display_rows 重排全部转录（万行 × 逐字形） 追加式布局（硬要求，非优化项）：指纹改为「已布局末行的原始偏移」； 新 chunk 只布局增量段，display_rows 原地 push。live 时重排成本 O(全量) → O(增量)。 思路与现有 PopupLayoutCache 同构（追加模式），不推翻设计。
② 源串复制 live 分支每帧 full_detail_text() 全量 String 返回， 再 source.lines().map(Line::from) 把全部行克隆成 styled lines 弹窗持追加式 String + 已取字节偏移：增量取新文本追加；styled lines 只补新行； 无变化帧零复制（full_detail_len() 指纹已是 O(1)）。
render
（每帧固定账本）		 ③ 视口行 hit 表克隆 每可见行 display.hit_row() → PopupHitRow { cells: cells.clone() } 每帧每行克隆整张命中表，存入 surface.hit_rows 惰性命中表：body 尺寸、scroll 未变时 hit_rows 直接复用上一帧 （Vec 缓存于 popup 状态）；仅当 scroll/宽度/行数变化时重建。若鼠标未在弹窗内， 可完全跳过 hit 构建（surface.hit_rows 留空）。
④ 每帧 spans / header 重建 每可见行 spans() 重建 Vec<Span>； header 每帧 format! + title.clone()； chrome / scrollbar 状态每帧重建 spans 仅视口行（已有 skip/take）；header 文本缓存（内容/宽度变化才重算）； chrome 块小、scrollbar 状态 O(1)，保留每帧重建（已是最小实现）。
⑤ 跟随底部滚动推进 底部跟随 = 每帧 scroll 前进一行，触发全量可见行重绘（②③④联动） 跟随时的重绘本就只覆盖视口行；配合增量布局，scroll 推进只追加尾行。 断点：手动滚动即停跟随（f 切换），避免滚动不断前进时的高频全量路径。
内存 ⑥ 行结构 每行 Vec<DisplayGrapheme>（每字一个）+ cells 命中表， 万行转录可达数十 MB 行缓冲改按段（span）存储，同段字符合并；命中表按「段起始 + 段宽」区间存。 目标：单行常驻从 ~2KB → ~200B；弹窗整体 < 10MB（万行级）。
循环层 ⑦ 帧节流 / chunk 合并 每个 ToolProgress chunk 立即触发重建（on_tool_progress 每 chunk 一次） chunk 到达只追加缓冲，每帧至多一次 prepare+render；同帧多 chunk 合并。跟随底部时增量布局只推尾部，光标动画独立于重排（不触发布局失效）。
⑧ 块收束不重排 thinking/tool 块的收束状态切换会改变视口行数 → 潜在整视口重绘 收束切换时只重排该块的 display_rows 区间（块边界已在布局中记录），前后行不动；配合 ③ 复用 hit 表。

验收基准（基准测试守卫）：万行（~1MB）转录连续流式输入时 —— 单帧布局 < 2ms（增量）、 弹窗常驻内存 < 10MB、滚动/选择响应 < 16ms（一帧）。新增测试用 10k 行合成转录断言 「增量追加 ≤ 全量重排 × 1%」与「每帧固定账本 ≤ 0.5ms」；任何回归到全量 O(n) 的路径都会被测试拦下。

04 交互规格

交互行为
打开内联卡双击（或聚焦卡后 Enter），任意阶段都可打开
常驻保持打开后一直保持；子代理结束（StepFinished / StepFailed）不关闭——只是流停止增长，弹窗继续展示完整转录，直到用户关闭
滚动j/k / ↑ / ↓ 逐行；g 顶、G 底
跟随Live 默认底部跟随；f 切换跟随/固定；手动滚动即暂停
收束块聚焦到 thinking/tool 块上时 ⏎ 切换 3 行卡 / 全文；块以光标停留为当前块
选择左键拖拽选段（PopupTextSelection，UTF-8 安全）；块边框不参与选择
拷贝y：有选区拷选区，无选区拷全部（含块内全文）
关闭Esc / ✕；Clear 覆盖 ≥ 绘制区（无残影）

05 数据与影响面

  • 状态类型 SubagentPopup：保留 tool_id / scroll / selection / layout_cache；新增 follow_bottom、duration、tokens、块收束集合、last_layered_offset（增量布局水位）；一个 live 布尔区分"流增长中 / 已结束"（只影响光标与徽章脉冲，不是状态页）。
  • 渲染 render/popups/subagent_popup.rs：单一实时流视图（live 与结束共用同一布局）；正文按「thinking 卡 / tool 卡 / 线性段」三类布局，复用主区域 ThinkingCell 的卡内行数算法（1+3+1）。
  • 常驻语义：on_step_finished 只更新 live=false 让光标/脉冲停止，不关闭弹窗；handlers/overlay.rs 新增 f、⏎ 分支。
  • 性能实现：selectable_text.rs 的 DisplayRow 改为「段存储 + 区间命中表」；PopupLayoutCache 支持追加式增量布局（指纹含末行偏移）；components/tool.rs::on_tool_progress 每帧合并一次。全部配 10k 行合成转录基准测试。
  • 数据层前置（与 stream 分段设计共享）：ToolOutputChunk 带段类型、subagent_ui.rs 按事件跨度打标（thinking 一段 = Started…Finished；工具一段 = Started…Finished/Failed）、user 段注入。
  • I18n & 文档：i18n.rs 徽章/快捷键文案；同步 docs/tool_rendering.md、book/ 相关章节（AGENTS.md 同步表）。
