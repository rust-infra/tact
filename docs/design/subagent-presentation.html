Subagent 会话怎么呈现

调研 + 重设计。起点是两张实机截图：弹窗里堆着主日志的工具卡，卡底写着 Click for full code / [ Open ] —— 在一个弹窗里承诺再开一个弹窗。

结论：问题不在「弹窗里怎么排版」，而在「子 agent 的会话该不该离开主日志」。
三个开源项目的答案是一致的 —— 不弹窗。要么把子 agent 的步骤嵌进主日志（Crush），要么进入子会话把它当成一个视图（OpenCode / Roo Code）。 弹窗这种容器天生不适合承载「可继续下钻」的内容：它自己就是一层 overlay，再叠一层就没人说得清 Esc 该关哪一层。

一、开源怎么做

项目做法关键机制（源码/文档里读到的）
Crush
charmbracelet · Go		 内联嵌套 子 agent 的工具调用是父工具调用这一条消息的子项，在同一个聊天流里按树渲染： NestedToolContainer 接口 / nestedTools []ToolMessageItem； AgentToolRenderContext 先画子 agent 的 prompt，再用 tree.Root 把 nestedTools 逐个当孩子画出来。子项用 simple / compact 渲染 （AddNestedTool 里标记），比顶层卡片轻。父项 Animate 会 bump 自己的 list-cache，让嵌套项的 spinner 也能转。子会话用 CreateTaskSession + ParentSessionID 建，费用回传父会话。
OpenCode
v2 TUI · TS		 进入视图 「你在一个 subagent 的 session 里面」是一个真实状态：/subagents 面板列出 root 会话的全部子 agent（含孙），按深度缩进，行首是任务名 + 括号里的 agent 名； enter 打开选中的子会话（面板不关），› 标出你当前在哪个 session，f 全屏，esc 关面板。 进入子会话后，TUI 在输入框上方显示一行实时状态（状态点 / 标签 / 模型 / 耗时 / tokens / ctx%）。 内置 TUI 对子会话故意不渲染输入框 —— 进去是看，不是接着说。
Roo Code
VS Code 扩展		 进入视图 子任务是 LIFO 任务栈（ClineProvider 管）：new_task 压栈、当前视图整个换成子任务、完成后弹栈回到父任务。返回是一层，不是关一个弹窗。
Claude Code
保守派		 默认收起 子 agent 的细节默认不展开：主日志里只留 Task 工具那一行 + 摘要，要看细节得显式切到更啰嗦的视图。 （这条是按它的公开文档与使用习惯归纳的，没有源码可引 —— 前三条有。）

共同点：没有一家把子 agent 的会话做成模态弹窗。要下钻，就换视图（有层级、Esc 只退一层）；要偷看，就嵌在当前流里（有父子缩进，不打断阅读）。

二、现在的问题

Rg 的两张截图，其实是同一件事的两面：把主日志的「可交互卡片」整套搬进了弹窗。

✗ 卡片承诺了一个不该存在的弹窗

在日志里，Click for full code 打开的是一层 overlay 盖在普通视图上，说得通。 在弹窗里，它是弹窗盖弹窗：谁在下面、Esc 先关谁、滚动归谁，全都没有答案。而且它现在点了没反应（没接路由）。

✗ 三层边框套娃

  • 弹窗边框 → 工具卡边框 → 输出卡边框。一屏里三次同样的圆角。
  • 每条工具调用 ~6 行起（2 行头 + 4 行卡），而它承载的信息是「跑了什么 / 成不成 / 输出了什么」。
  • 主日志的卡片之所以长这样，是因为它在一条流里要压到 2 行并靠 [ Open ] 兜住全文；弹窗里既没有那个约束，也没有那个出口。

三、第一步（已落地）：弹窗内改成自包含块

先把「借来的交互」拿掉：工具调用与思考都渲染成无边框、无 [Open]、自包含的块 —— 左侧一条 rail，输出封顶并计数而不是给按钮。

工具调用 3 行 + 预览；思考全文（它只在这里可见）；助手文本照旧 Markdown。 没有边框、没有 [Open]、没有「点一下再看」。块底部那行计数就是展开键，y 复制命令与输出—— 而且块行本身可以拖选（rail 只占格不占字节，高亮从正文开始）。

✓ 为什么思考全文、工具输出封顶

  • 子 agent 的推理只在这里可见（日志里的思考卡属于父级），封顶等于藏起来。
  • 工具输出不同：它在父日志的卡片里还有出口，而一份 500 行的 grep 倒进转录会把会话埋掉。
  • 所以剩下多少行就写多少行（⋯ 34 more lines），不给按钮 —— 按钮就是下一个弹窗。

✓ 顺手修掉的两处

  • $ <command> 不再重复：详情卡为弹窗准备的那行参数行被丢掉，标题里已经有命令。
  • 命令的输出取尾部（和主日志 ToolWidget::build 一致），其他取头部。
  • 块内换行在建段时完成，所以 rail 出现在每一个视觉行上（不是只第一行）。

四、第二步（已落地 2026-10-11）：换容器 —— 进入视图，弹窗退役

第一步只是让弹窗「不再说谎」。按上面的调研，正确的做法是换容器： 给子会话一个真正的视图，而不是一个 overlay。这一步先做。

1

进入一个视图（OpenCode / Roo Code 做法）—— 已落地

面包屑 ‹ 4. Subagent · code review，主区域整体换成子会话，esc 退一层。在这一层里，工具卡可以恢复成主日志那种可交互的形态 —— 因为 overlay 盖在视图上是正常的分层，盖在弹窗上才是套娃。这就是「不能硬搬主 agent 交互」的真正边界：交互可以借，容器不能借。

实机取舍（Rg：「不用和主 agent 一致」）：视图里的工具块没有恢复成可交互卡片，仍是自包含块（▎ N. ⚡ Bash args / ✓ Success · 133ms · 42 lines / code band / ⋯ N more lines）—— 输出封顶 8 行。但块底部那行计数本身可点：⋯ 4 more lines · ▾ expand 点开把这一块提到 50 行，同一行随后变成 ▴ collapse。粒度是每块（子 agent 实测 34 步，一次展开全部会把要找的那段埋掉），Enter 是「全部展开 / 全部收起」的批量键。面包屑整行是返回键的鼠标面；提示画在面包屑右侧（视图没有 footer）。

为什么不是先做内联：Tact 的子 agent 跑的是完整 agent loop（那张截图 34 步、thinking 1/160 lines），内联进父日志会把父对话埋掉；而且 Tact 的子 agent 不能再 spawn 子 agent（subagent_toolset() 里没有），深度恒为 1 —— Crush 的树、Roo 的栈都退化成一层，不值那个复杂度。内联的紧凑形态留给卡片行内预览。

2

（可选，之后）短会话内联（Crush 做法）

几步就回的短会话可以直接挂在卡片下面看；长的仍然走视图。默认收起，只留尾部几行。

3

弹窗退役 —— 已落地

现有 SubagentPopup 的键盘/鼠标路由（j/k、g/G、拖选、y）已平移到视图上，overlay_popup_* / has_overlay_popup / 底部 overlay 列表里那条 subagent 分支已删掉；kit 的 chrome 版 render_subagent_popup（零调用者）与 title_close_suffix_width 也已删除，只留 render_subagent_body 给视图外壳。粘性条（[Subagents] 1/2 · …）已经在做「有哪些在跑」。

五、必须钉住的不变量

  • 结构来自子 agent 的结构化更新（AgentUpdate::ToolTranscript），不从扁平文本反推 —— 这条已经在实现里。
  • 运行中与完成后同一套渲染：助手文本运行中就是渲染后的 Markdown，结束时只有状态词与行数定格。
  • 块不承载交互：没有可点的字形，就没有「点了没反应」和「Esc 该关谁」。
  • 换行在构建期完成，rail 是每行的一个 span —— 交给事后 wrap_line 切，rail 只会留在第一行。
  • 脱敏两条通道都要过：结构化通道是另一个发送口，绕过 redact_text 就等于把扁平流抹掉的东西又放回来。

阶段划分

  • 已完成：结构化转录 + 自包含块（本文第三节）。
  • 已完成（2026-10-11）：视图 + 面包屑 + esc / 点面包屑退层 + 块底部溢出行可点展开（Enter 批量）；弹窗退役（render_subagent_popup 删除）。
  • 未做（可选）：短会话内联（Crush 那一步）—— 见上面第 2 条。
