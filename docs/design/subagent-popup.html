Subagent 弹窗重绘

历史稿（2026-10-10）：本文描述的是弹窗形态。2026-10-11 定案改成视图（主区域整块换成子会话 + 面包屑 + Esc / 点面包屑退层 + Enter 展开工具块），弹窗与 chrome 版渲染器已退役——见 subagent-presentation.html、subagent-oss-comparison.html 与 spec §8/§9。下面的「结构化转录」与「自包含块」两条仍然成立，块形态就是视图里用的那一种。

移植说明：Ported onto the post-migration layout (2026-10-12).

现在：子 agent 的整条会话在转发时被压成一坨纯文本——工具调用靠 →、结果靠 ✓、思考靠 🧠 Thinking 三个 emoji 前缀区分，全篇一个颜色；live 是纯文本、结束的瞬间又整段过一遍 Markdown，同一段话会重新排一遍。

重绘：让弹窗用主 agent 同一套渲染单元（工具卡 / 思考卡 / Markdown 单元格），数据来自子 agent 自己发出的结构化更新——不是从文本里反推结构。

✗ 运行中：一坨同色纯文本

  • 整段是 Line::from(text)，全部用 theme.fg —— 分不出「谁在说」。
  • → web_search bitcoin price usd 长得跟正文一模一样：没有工具名分层、没有参数/结果之分、没有耗时。

✗ 完成后：同一段话重排一遍

  • Prompt: 与提示词粘成一行（模板里是单个 \n，Markdown 软换行 = 空格）。
  • 段落之间的空行、→/✓ 行全部变成普通段落——工具结果读起来像正文。
  • live 看的是一套排版，结束看的是另一套。滚动位置也跟着跳。
  • 根因：转发层只留了文本，结构在进 UI 之前就丢了。

  • 标题行：{步骤号}. Subagent · {child_id 前 8 位}。
  • meta 行（muted）：🤖 model · ⚡ 12.4K tok · ⏱ 00:41 · ● running · 214 lines。

  • 这些数据今天已经躺在 ToolMeta 里（卡片头在用），弹窗只是把它们也画出来。

✓ 正文：结构驱动的块（不是搬主 agent 的卡片）

  • 提示词 → Markdown 渲染的文本段（带 💬 前缀）。它是父级生成的任务简报， 不是人打的字 —— 主日志把 user 行画成纯文本，但这里照原样显示 ## / ** 会让弹窗里一定会看到的那一段看起来是坏的。
  • 助手文本 → Markdown 渲染成可选中的文本段（按「段」合并 StreamChunk），live 就渲染 Markdown。
  • 思考 → 自包含块（▎ 🧠 Thought · ⏱ 1.2s + 全文）。
  • 工具调用 → 自包含块（▎ N. 🔍 Web Search args + ✓ Success · 1.4s · 3 lines + rail 输出 + ⋯ N more lines）。标题/阶段词仍来自 ToolWidget，所以与主日志同源；但不画边框、不画 [ Open ]。
  • Info / Error → 系统色文本行（error 用 theme.error）。

D · 三个必须钉住的点

① 数据：新增一条结构化通道

  • 新 AgentUpdate::ToolTranscript { tool_id, entry }，entry 是 SubagentTranscriptEntry（Assistant / Thinking / Step / Info / Error）。
  • 由 tool/subagent_ui.rs 的转发器发出——它已经在 match 每一个事件了，只是今天全部转成字符串。
  • 扁平文本保留：卡片那 8 行 live 预览和 y 复制仍走它，但它不再是弹窗的数据源。
  • transcript 存在 ToolState 的旁路 map（key = tool_id），不放进 ToolRenderOutput——后者每帧被 clone，塞进去会每帧复制整条会话。

② 渲染：复用 LogColumnRenderer

  • 弹窗正文 = 一串「段」：文本段（TextCell/MarkdownCell）或卡片段（ThinkingCell/ToolCell），每段记 vis_start + height。
  • 丢进 LogColumnRenderer::with_viewport(scroll, height)，由它做视口裁剪——和主日志同一个渲染器，不新写一套行循环。
  • 缩进沿用主日志常量：思考卡 LOG_THINKING_INDENT(2)，工具卡 LOG_TOOL_BLOCK_INDENT(8)。
  • 布局缓存的 key = (transcript 版本号, 宽度, 主题, live 标志)；transcript 只在追加时 +1，所以帧间不重排。

③ live == 完成后

  • 今天 prepare 里有个 is_live 分叉：live 走纯文本、完成走 Markdown。这个分叉删掉。
  • 助手文本段在 live 就按 Markdown 渲染；只有最后一段会随流增长重渲，且仅在其长度变化时（沿用现有 content_len 指纹）。
  • 结束时不再重排、不再跳滚动位置——SubagentFinished 只改 meta 行的状态词。

④ 选择 / 复制照旧

  • 可选中文本 = 所有文本段按顺序拼接（提示词 + 助手文本 + 思考正文 + 工具参数与结果 + Info/Error），每段记自己的字节区间。
  • 只有文本段画选中高亮；卡片行（思考卡边框、工具卡头）不可选——和主日志一致（日志里 ToolCell 也不是选择目标）。
  • y 无选区时复制整条 transcript；有选区时复制选区。

E · 交互：只加不改

j/k ↑/↓ 滚动· g/G 顶 / 底· 拖选 + y 复制· Esc 关闭

滚动单位从「显示行」变成「视觉行」——因为卡片有高度。键位、footer 文案、鼠标命中路径都不变。

下一步：换容器（不是把交互接回弹窗）

  • 换容器，而不是把交互接回弹窗。调研三个开源项目（Crush / OpenCode / Roo Code）后：正确的下一步是把块嵌进主日志（Crush 做法），或把子会话做成可进入的视图（OpenCode 做法）——在视图里工具卡可以恢复成可交互形态，因为 overlay 盖视图是正常分层，盖弹窗才是套娃。
  • 见 docs/design/subagent-presentation.html。
  • 子 agent 内部的权限请求（RequestSelect）在弹窗里就地渲染成一行 ⚠ [Subagent] Allow bash?，而不是只在父级弹模态。

不做什么

  • 不动父级 spawn_subagent 卡片本身（2 行头 + 8 行 live 预览 + Summary 卡）。
  • 不做「回合分隔线」——主日志也没有，助手文本/思考卡/工具卡本身已经把回合切开了。
  • 不从扁平文本里反推结构（那是今天简陋的根因，且任何前缀改动都会静默失效）。
