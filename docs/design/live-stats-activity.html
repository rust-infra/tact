实现说明

动画挂在哪 已定

  • 唯一位置：render_live_stats_band（agent_tui_kit/src/render/stats_line.rs:143）。它只在 ctx.task_start_time.is_some() 时被调用（render/log.rs:510）——「处理中」的判定是现成的，不用新增状态。
  • 帧号现成：ctx.spinner_frame，非 Idle/Done 每帧 +1 % 10（tui/src/lib.rs:348），active 状态 poll 超时 150 ms（tui/src/lib.rs:414）。
  • 零额外唤醒：不需要新定时器、不需要新 repaint 理由。

字形现成 复用

  • TOOL_RUNNING_SPINNER（widgets/tool_widget.rs:24）：⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏，与工具行、loading 占位同一套。
  • 用户在同一个界面里已经学过这套「正在跑」的词汇 —— 新增的动效不需要教学成本。

不能做的事 硬约束

  • 不要把动画字形塞进 task_stats_body。它是 live 行与 frozen 行的唯一来源，frozen 行的 raw 必须与绘制行逐字形一致（选择/点击映射依赖它）。动画只在 live 分支拼前缀，body 原样。
  • frozen 行不画转圈：那是已经结束的回合，转圈会撒谎。
  • C 方案的行尾仍必须是 theme.bg（AGENTS.md：每个渲染单元把自己整块 area 刷成自己的 bg）。

代价

  • A / D：前缀占 2 列 → 回合结束交接时整行居中位置左移 1 列。center_pad 的 ±1 已在 log_render_tests 容差内。要完全不动就把前缀压成 1 列（字形后不留空格）。
  • B：不改布局，只改 ⏱ mm:ss 的 fg（accent ↔ 暗一档的 accent），交接时逐格一致。
  • C：唯一真正新增绘制单位的方案（一行 per-cell bg 带），也最容易被误读成「选中高亮」——建议做成可选，不进默认。

跑马灯的实现代价 唯一要新增状态

  • 需要一个新的单调计数：spinner_frame 是 % 10，按列推进太短。在同一个地方（tui/src/lib.rs:348）加一个 App 字段、plumb 进 RenderCtx —— 一行改动，但确实是本组唯一的新状态。跑马灯和吉祥物共用这一个 tick，不会各加一个。
  • 溢出判定顺带修一个静默裁切：现在行宽超过面板时 center_pad 算出 0，尾部 token 明细被切掉、没人看得见。按 UnicodeWidthStr::width(前缀 + body) > area.width 分流，溢出才跑。
  • frozen 行仍然是静态日志行（不跑），所以溢出场景下它照样被裁 —— 要彻底解决得让 frozen 行折行，那是另一件事。
  • 交接瞬间会跳：跑马灯停在中途，frozen 行回到居中（A/B 只差 1 列，跑马灯可能差几十列）。
  • 动的是位置不是字形 → 与 A/B 正交、可叠加，但叠起来很吵。

吉祥物：跑得起来的前提 关键取舍

  • 跑道只有两个来源：R1 文字两侧的留白（0 行成本，窄终端自然消失）；R2 统计行上方多留 1 行（全宽跑道，代价是任务在飞时少一行日志）。
  • 两侧一起跑是白送的：R1 的左右两条留白本来就是空的，同一个 pos 镜像到右边（cols-1-iconW-pos）就多一只，0 行成本。右跑道默认用「第二只」（set.pair[1]：猫在左、狗在右）。
  • 左右两条跑道是断开的 —— 中间隔着文字，两只永远不碰面。这是设计的一部分，不是缺陷：图标横穿文字就会吃掉数字。镜像位相让它们同时往里、同时掉头，看起来是一对而不是各跑各的。
  • R1 的短跑道反而更可爱：19 列、来回 5.4 s，节奏刚好；R2 的 121 列要 36 s 一趟，不加速就像在爬。宽跑道 ≠ 更好看。
  • R2 有个白送的好处：图标行在文字行上方，frozen 行接手时落在文字行上 → 文字一格都不动，比 A/B 的 1 列位移更干净。
  • 图标绝不横穿文字：那一行的每个格子都是数字，压过去就是吃掉读数。所以跑道只能是留白或专用行。
  • 「蹦跳」只能是字形交替：这一行只有 1 行高，真的上下跳要 2 行跑道（即 R2 再 +1 行）。所以 J 那一行是两只交替出现，看起来像在蹦，其实没动高度。
  • 走位要按「步」算，不能按列：一帧走 N 列时，pos = tick * N 会直接跳过端点 —— 图标永远碰不到尽头，转身帧几乎不触发（实测 4 列/帧时 24 帧只命中 1 次）。正确做法是先算单程步数 ceil((L-1)/N)，再把位置夹到端点；改完三档速度都能稳定命中（6/30）。
  • 方向翻转的真相（把字形放大到 52px 逐个看过，不是猜的）：终端不能镜像字形（一个码位一个字形，全库带 _mirrored 的只有几个像素方块和火焰）。但动物不是「只有一个朝向」那么简单：
    · 对称的动物根本不用翻：md-cat md-dog md-panda md-penguin md-rabbit md-turtle md-butterfly md-bee md-bug md-owl md-cow md-sheep 都是正面/俯视 → 来回跑都自然。「动物 · 对称」那一组就是答案。
    · 侧视的动物天生分左右两拨：朝右 md-dog_side 󰩄、md-fish 󰈺、md-run；朝左 md-bird 󱗆、md-duck 󰇥、md-dolphin 󱢴、md-snail 󱙷、md-horse、md-unicorn 󱗂、md-elephant、md-rodent。右向一只 + 左向一只 = 真朝向掉头（「动物 · 侧视」那一组）。
    · 剩下的（md-run 那族、非对称符号）没有左向字形 → 自动退回尾迹。
  • 字形全部取自本机 Nerd Font 的真实 cmap（JetBrainsMonoNFM / HackNFM / 0xProtoNFM），不是猜的码位；实测每个图标的 advance 与 0 完全相同 → 正好 1 列宽，不会挤动文字。

吉祥物的风险

  • 字体覆盖：PUA 图标没有 Nerd Font 就是豆腐块。Tact 已经在用 󰜼（[󰜼 Open] 按钮），所以 Nerd Font 事实上已是既成要求 —— 但那是可点击的按钮，一个装饰性吉祥物渲染成豆腐更难看。
  • 兜底：纯 Unicode 那组（✦ ♥ ★ ✿ ☾）任何字体都有；ASCII 鱼（><(((°>）连方向翻转都是白送的，零字体风险。
  • 建议做成配置（[ui] stats_mascot = "cat" | "off"），默认 off 或 unicode；不要默认开一个可能变豆腐的 PUA 字形。
  • 别用 emoji（🐱）：宽度 2，会把跑道数学和文字对齐一起搞乱。

跑马灯的 UX 代价

  • 计时器和 token 数变成移动靶，一眼读不全 —— 而这一行存在的意义就是「不用翻日志就能看数」。
  • 正在用鼠标翻上面的日志时，底部一直在动是干扰。
  • 所以：E（滚动）只在溢出时启用，是功能性的不是装饰性的；F（往返漂移）不建议进默认，它只是「看起来在跑」，代价是读数变累。
  • 想要「跑马灯的感觉」又不想付这个代价 → 用 C（灯带跑马）：字不动、光在跑，零新增状态、零信息损失。
  • 如果目标其实只是「溢出不丢信息」：更省事的办法是让这一行在溢出时折成 2 行（LIVE_STATS_ROWS 1→2）—— 静止、可读、零动效。跑马灯是「就是想要它动」才选的方案。

推荐 A + B

  • 前缀转圈说「在跑」，计时器呼吸说「还活着」，两者共用同一个 spinner_frame，不新增任何状态或定时器。
  • 单独用 D（只跳一个点）偏弱；单独用 C 信息噪声大。
  • 备选 A′：live 行把 ⏱ 换成 spinner 字形（同槽位）。更省列，但打破 Task stats:⏱ 的形态一致，且 the_live_row_hands_off_to_the_frozen_row 的断言要改。
