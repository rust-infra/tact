四家怎么呈现 subagent —— 效果与交互

Crush / OpenCode / Roo Code / Claude Code。每节画一张「长什么样 + 怎么操作」，

移植说明：Ported onto the post-migration layout (2026-10-12).

并标出哪些是源码/文档确证、哪些只是形状示意。

共同点：没有一家把子 agent 的会话做成模态弹窗。 要偷看就嵌在当前流里（Crush），要下钻就换视图（OpenCode / Roo Code）， 再不然就另开一个 pane / 事后重开 transcript（Claude Code）。 Esc 永远只退一层 —— 因为层级是真实的，不是叠出来的。
项目做法子 agent 的内容出现在哪进去 / 出来的手势
Crush内联嵌套 父工具调用那条消息下面，同一个滚动里，按树缩进；子项用 compact 渲染 不需要「进去」：它就在当前流里。展开/收起 = 收放同一棵子树
OpenCode进入视图 子会话是独立 session；/subagents 面板列出来，enter 打开 enter 进 → esc 退；面板 esc 关；› 标当前所在
Roo Code进入视图 子任务压栈，整个视图换成子任务 弹栈返回（Back to parent）；一层一层退
Claude Code收起 + 另开 主日志只留 Task 一行 + 摘要；细节在 transcript；teammate 直接另开 pane 背景 agent 以 task notification 回来，需要时重开 transcript

1Crush — 子 agent 的步骤是父调用这条消息的子项 机制：源码确证 字形：示意

父项画完自己的 prompt，就用 tree.Root 把 nestedTools 当孩子逐个画出来。 子项被标成 simple / compact，所以一层嵌套只占一行 —— 这是它敢内联的前提。 父项 Animate 会 bump 自己的 list-cache，所以嵌套项里的 spinner 也在转。

crush · ~/Projects/tact · deepseek-chat
⏺ agent(Explore the repo structure and report back)
⎿ prompt · "Explore the repo structure…"
├─ ⏺ view(internal/ui/chat/agent.go) · 214 lines
├─ ⏺ grep(NestedToolContainer) · 7 hits
├─ ⏺ bash(go test ./internal/ui/...) ✓ 2.1s
└─ ⏺ agent(check the session store) · nested one level deeper
└─ ⏺ view(internal/store/session.go)
⏺ Explore complete · 4 tool calls · 1m 04s · $0.04
⏺ Reading the tree, three things stand out…
不需要「进入」 ↑/↓ 在同一个流里滚 展开/收起 = 收放同一棵子树

为什么这样最好用

  • 零导航成本：你本来就在读这段流，子 agent 的步骤就在下面几行，不用「切过去再切回来」。
  • 层级是画出来的：缩进 + 树线一眼看出「这是谁的孩子」，比一个标题栏里的面包屑便宜。
  • 子项必须更轻：compact 一行一个。若子项也用顶层那种卡片，嵌套两层就把屏占满了。

对 Tact 的启示

  • Tact 的 spawn_subagent 卡片已经在日志里，只差「把子项画在它下面」。
  • 子项的行格式就是我们已经做好的自包含块（▎ N. ⚡ Bash args + 阶段行 + rail 输出）。
  • 难点是滚动与占位行：日志的行数要随子项增长重算（Tact 已有 ToolEvent::Resize 这条通道）。

2OpenCode — 子会话是另一个 session，你「走进去」 面板行格式：文档实例 布局：示意

「我在一个 subagent 的 session 里面」是一个真实状态：面板里 › 标出你当前在哪， enter 打开选中的子会话（面板不关）。进去以后输入框上方多一行实时状态。 内置 TUI 对子会话故意不渲染输入框 —— 进去是看，不是接着说。

① 子 agent 面板（/subagents）

opencode · main
Subagents 2 run · 1 done · 0 err
● RDD review lens retry
(review-reliability)
↳ ⏱ 05:05 1,564 tok · 37% ctx
◌ review the parser fix (review-validator)
↳ ⏱ 00:12 · 3.1k tok
› ✓ build the release · claude-sonnet-4-6
↳ ⏱ 01:04 8.0k tok · $0.04 · 12% ctx
● docs · claude-sonnet-4-6 · ⏱ 00:03 · 1.2k tok ⚠
j/k move · enter open · c completed · f fullscreen · esc close

行 = 任务名（不是 agent 名：同一个 agent 的多个子 agent 会同名）+ 括号里的 agent； 按深度缩进，孙 agent 挂在父下面；⚠ = 有权限请求在等人；› = 你现在就在这个 session 里。 排序是「先需要你的」：待权限 → 运行中 → 最近活动。

② 走进去之后（子会话视图）

⏺ read scripts/check-rust.sh

┌──────────────────────────────────────────────────────────────────┐
│ （子会话没有输入框 —— 进去是看，不是接着说） │
└──────────────────────────────────────────────────────────────────┘
enter 打开选中的子会话 esc 关面板 / 退一层 j/k 移动 c 显示/隐藏已完成 f 全屏

为什么这样

  • 子会话本来就是独立 session（有 id、有 parentID、有自己的消息），所以「进去」是切 session，不是渲染一个弹窗。
  • 面板是导航中枢：多个子 agent 并行时，你需要先看「谁在等我」，而不是先看某一个的内容。
  • 状态行放在输入框上方：进去之后最想知道的是「这是谁、跑多久了、花了多少」。

对 Tact 的启示

  • Tact 的粘性条（[Subagents] 1/2 · focus · …）已经在做「面板」那半件事，只差 enter。
  • Tact 的子 agent 也有 child session id —— 视图有天然的身份。
  • 关键边界：视图里可以恢复可交互卡片（overlay 盖视图正常）；弹窗里不行。

3Roo Code — 子任务是栈，整个视图换掉 机制：文档确证 界面：示意（VS Code webview）

new_task 压栈：当前视图整体换成子任务；子任务再 new_task 就再压一层。 返回是弹栈 —— 一层一层退，不是关一个弹窗。注意它是 GUI，不是 TUI，所以「视图」的代价比终端里小得多。

Roo CodeTask 2 / 3subtask ← Back to parent
[parent] Implement the parser fix
└─ [current] Write regression tests for the parser fix (test mode)
Roo: I'll add a focused test for the escaped-quote case first.
⏺ write_to_file tests/parser_escapes.rs
⎿ +42 lines · created
⏺ execute_command cargo test -p tact --lib parser
⎿ 3 passed · 0 failed
↩ Sub-task finished — handing the result back to the parent task…
Back to parent 弹栈返回 Task 2 / 3 层级深度可见 子任务完成 → 结果自动回注父任务

为什么这样

  • 上下文是干净的：视图里只有子任务的对话，父任务的噪声一点都进不来。
  • 深度是有限且可见的：栈是 LIFO，Task 2/3 直接告诉你还有几层。
  • 代价：你要「离开」当前任务才能看子任务 —— 在终端里这比在 GUI 里贵（终端只有一块画布）。

对 Tact 的启示

  • Roo 和 OpenCode 是同一个答案的两种实现：子会话是一个可以被进入的位置。
  • Tact 的 Esc 已经是「退出当前视图状态」的梯子（slash 弹窗 → 语音 → 退 Insert → 清选区）， 「退出一层子会话」正好能插进去 —— 概念是现成的。

4Claude Code — 默认收起，要细节另开一处 机制：文档确证 界面：未核对，仅画机制

它不给子 agent 做「内联展开」也不做「视图切换」，而是三条路：① 主日志只留 Task 一行 + 摘要； ② 背景 agent 注册进 task 系统，完成时以 task notification 回来，必要时重新打开 transcript； ③ teammate 直接另开一个 pane（tmux / iTerm2 split），每个 pane 是一个独立的 CLI 进程。

claude · ~/Projects/tact
⏺ Task(Explore the codebase) · 12 tool uses · 12.4k tok · 1m 04s
⎿ Done — the agent loop lives in crates/tact/src/agent/mod.rs …
（子 agent 内部的 12 次工具调用默认不在这里展开）
⏺ Task(Run the release build) · running in background
… 你可以继续问别的问题，它跑完会回来找你 …

⎿ reopen transcript · /tasks

teammate：另开 pane（不是另开弹窗）

tmux
┌────────────────────────────┬────────────────────────────┐
│ leader │ teammate (own process) │
│ │ │
│ ⏺ Task(Explore…) │ ⏺ grep(NestedTool…) │
│ ⏺ Task(Run release…) │ ⏺ bash(go test ./…) │
│ │ idle · waiting for a msg │
└────────────────────────────┴────────────────────────────┘

它的取舍

  • 主日志永远干净：子 agent 无论跑多久，父对话里就是一行。
  • 「另开」比「内联」便宜的地方：pane 是操作系统级的窗口，不用管行数、滚动、重排。
  • 贵的地方：你要自己看两个地方；终端里 pane 会挤，且不能像列表那样「按需进来」。

对 Tact 的启示

  • Tact 的 background subagent 已经走在这条路上（async_launched + <subagent-finished> 回注）。
  • 「完成后回来找你」这条 Tact 有了；缺的是「必要时重开 transcript」那个入口 —— 也就是弹窗本该扮演的角色。
  • pane 这条路 Tact 不适用（一块画布），所以只剩「内联」和「进入视图」两个选项 —— 和上面两家一致。

5落到 Tact：三种容器，一张表

容器谁这么做优点代价
内联嵌套
子项挂在卡片下		 Crush 零导航；层级用缩进表达；读完不用「退出」 日志行数要随子项增长重算；子项必须足够轻（一行一个），否则埋掉父对话
进入视图
主区域换成子会话		 OpenCode · Roo Code 上下文干净；可以恢复完整交互（卡片、Open、拖选都成立）；深度可见 要「离开」当前对话；需要面包屑 + 一层 Esc；视图状态要能记住
模态弹窗
现在 Tact 的做法		 没有一家 — 自己就是一层 overlay：再叠一层没人说得清 Esc 关谁；内容必须「自包含」，于是不能有交互
结论：Tact 该做「进入视图」，不是内联嵌套，更不是弹窗。 三条 Tact 自己的事实把天平压向视图（下面「为什么不是内联」一节）。 内联的形态不浪费：它就是卡片行内那几行预览该用的紧凑格式；而「进去之后」可以恢复主日志那套 可交互卡片 —— 因为 overlay 盖视图是正常分层。弹窗两样都不占，退役。

为什么不是内联（对 Tact 而言）

  • 体积对不上。 Crush 内联的是短探查（几步就回），子项是 compact 一行。 Tact 的子 agent 跑的是完整 agent loop —— Rg 那张截图里是 34 步、 thinking 卡显示 1/160 lines。这个体量内联进父日志，等于把父对话埋掉。
  • 深度恒为 1。 Tact 的子 agent 不能再 spawn 子 agent （subagent_toolset() 里没有 spawn_subagent）。 所以 Crush 的树、Roo 的栈都退化成「一层」—— 树线和 Task 2/3 都不值那个复杂度。
  • 缺的是容器，不是位置。 子会话真正需要的是 [Open]、拖选、y 这些交互，而它们只在「非 overlay 的容器」里合法。

为什么是视图

  • 改动最小。 渲染器、选择、滚动、键位都已经写好 —— 只是把容器从 overlay 换成主区域， 加一行面包屑和一级 esc。
  • 入口已经有了。 粘性条 [Subagents] 1/2 · … 已经在列 running/done/failed， 它就是 OpenCode 那个面板。
  • 身份已经有了。 子 agent 本来就有 child session id， subagent_popups 也已经按 tool_id 存滚动/选区 —— 平移即可。
  • Esc 梯子已经存在（slash 弹窗 → 语音 → 退 Insert → 清选区），「退出一层子会话」直接插进去。
