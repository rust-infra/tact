# Agent SDK Implementation Plan

> **For agentic workers:** Follow the tasks in order. Keep each task independently
> reviewable and do not start the next phase until its gate is green. Use
> checkbox syntax (`- [x]`) to track implementation.

**Goal:** Add `tact_agent_sdk` as a thin, ergonomic facade over
`tact_agent_api` and `tact_agent_core`, with safe defaults, session ownership,
static tool composition, and optional tracing-compatible telemetry.

**Architecture:** The kernel remains stateless across activations.
`AgentBuilder` collects capability implementations, `Agent` shares a composed
kernel, and `AgentSession` owns one `AgentState`. Tools compose through
`ToolHandler` and `ToolProvider`, not a runtime registry. Telemetry is added by
internal capability wrappers and a semantic event observer.

**Tech stack:** Rust 2024, async-trait, Tokio, serde, uuid, optional tracing,
existing kernel test support as dev-only fixtures, and the workspace dependency
guard.

**Spec:** [`docs/superpowers/specs/2026-10-28-agent-sdk-design.md`](../specs/2026-10-28-agent-sdk-design.md)

**Current status (2026-10-28):** implementation complete; focused checks and the full repository gate pass.

## Global Constraints

- Do not commit or push unless explicitly requested.
- Work on the existing feature branch; do not commit to `main`.
- Do not modify `tact_agent_api` or `tact_agent_core` merely to make the SDK
  convenient.
- Run one Cargo invocation at a time.
- Use focused tests while implementing; run the full gate once at the end.
- Keep `tact_agent_sdk` free of `tact`, `tact_llm`, `tact_protocol`, `tact-ui`,
  SQLite, MCP, provider HTTP stacks, and TUI dependencies.
- Keep the SDK's model required. Do not invent a default provider.
- Keep the default gate restrictive. Do not default to `AllowAllGate`.
- Keep tool resource access conservative. The default is a barrier.
- Keep content logging off by default and bounded when enabled.
- Do not install a global tracing subscriber from library code.
- Keep plugin style as static dependency inversion. Do not add a runtime plugin
  registry or lifecycle.
- Treat `KernelError` as the public runtime error and preserve its phase.
- `AgentSession::run_*` must require `&mut self`; do not add concurrent
  activation support in the first version.
- `AgentBuilder` must not own `AgentState`.
- Restored state must be initialized; an uninitialized state is rejected.
- The only optional SDK feature is `telemetry`.

## Review Focus

- The default graph can run a text-only agent with no tools.
- `BasicContextPolicy` returns all caller inputs.
- A tool-enabled agent requires an explicit gate.
- `max_total_turns(24)`, `Some(24)`, and `None` all have the intended
  semantics.
- A cancelled activation cannot cancel the next activation by accident.
- A custom context policy cannot be silently overridden by `system_prompt` or
  `model_options`.
- Telemetry spans measure actual stream and execution phases, not only future
  construction.
- Telemetry wrappers forward every default method.
- Telemetry does not become a global side effect.
- The SDK public surface stays smaller than the kernel surface.
- No product adapter, `tact_llm`, or provider HTTP dependency is copied into the
  SDK.

## Definition of Done

- The SDK is usable with `AgentBuilder::new(model).build_session(id)?`.
- The builder accepts `u32`, `Some(u32)`, and `None` for the turn cap.
- `BasicContextPolicy` returns all caller inputs and configured model options.
- Restored state is initialized and cannot be silently overwritten.
- `AgentSession` owns state, serializes runs with `&mut self`, and exposes the
  latest assistant message.
- Tools are static providers with a barrier-safe access default.
- Defaults are safe and documented.
- Cancellation is activation-scoped and stale-cancel-free.
- Telemetry is optional, host-controlled, complete, and content-bounded.
- The SDK has no product, provider HTTP, `tact_llm`, or UI dependencies.
- Examples, metadata, docs, dependency guards, and tests are complete.
