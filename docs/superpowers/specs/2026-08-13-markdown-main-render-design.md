# 主区域 Markdown 列表渲染设计

## 目标

在不重写 Markdown 解析器、不改变现有流式状态机、不引入黄色边框 callout 的前提下，修复 TUI 主日志区域中普通列表和嵌套列表的视觉布局问题，并确认主区域的滚动、窄宽度、表格、代码块和流式分段没有回归。

## 已确认的现状

- 流式文本由 `App::apply_stream_chunk` 按换行缓冲。
- 普通内容先积累到 `stream.paragraph`，在空行、表格、代码块或其他边界处 flush。
- 完成的 Markdown 片段通过 `tui-markdown` 渲染。
- 表格由 Tact 的 `format_table` 做宽度感知布局。
- 主日志区域随后对渲染出的 `Line` 按可用宽度做视觉换行并缓存。
- 弹窗路径已经有列表续行的悬挂缩进逻辑，但主区域路径没有等价的列表专用断行验证。

## 范围

1. 修复主区域普通 Markdown 列表的一级、嵌套、数字列表和长文本续行布局。
2. 确保中文和宽字符列表在窄窗口中不越界、不丢字、不产生错误的视觉高度。
3. 验证列表与表格、代码块、引用和 Mermaid 分段相邻时内容不丢失、不串行。
4. 验证主区域滚动缓存、宽度变化、极窄窗口和滚动到中间时不会裁剪或错位。
5. 保留现有流式渲染策略：未完成的 token 继续缓冲，已完成的 Markdown 片段继续增量显示。

## 非目标

- 不实现完整 CommonMark 增量 AST。
- 不更换 `tui-markdown`。
- 不新增 Markdown 语法扩展。
- 不把引用块渲染成黄色边框、背景色或圆角 callout。
- 不重构主区域布局、工具卡片或弹窗体系。

## 设计决策

### 1. 保留流式状态机

当前流式状态机已经分别处理普通段落、表格和代码块；本次只验证并修正其输出进入主区域后的布局，不把每个 token 重新解析成完整 Markdown 文档。

### 2. 在主区域视觉换行层处理列表续行

Markdown 解析器负责产生列表 marker 和内容；主区域换行层根据每一行的 marker 计算内容起始列，并让后续视觉行对齐到内容起始列。列表 marker 仍然属于可见文本，前缀空格不参与源文本选择映射。

### 3. 不改变表格和代码块的专用路径

表格继续由 `format_table` 在列内换行，代码块继续由已有代码卡片/流式代码路径处理。列表测试会覆盖这些结构相邻的情况，防止修复普通换行时误伤专用路径。

## 验收标准

- 长的有序列表项续行文本与首行正文起始列对齐。
- 无序列表、数字列表、嵌套列表和中文列表在足够窄的终端中不越界、不丢字符。
- 列表后接表格、代码块、引用或 Mermaid 时，所有源内容仍按原顺序显示。
- 流式输入在换行边界和未完成尾行边界都不丢文本。
- 宽度变化会重新构建视觉缓存，滚动到中间仍能显示正确的逻辑行。
- 现有 `tui` 渲染测试全部通过。
