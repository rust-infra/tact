# Native Shell (NSH) 0.3.0 Rust API cheat sheet

For porting a GPUI desktop app to NSH. Signatures below were read from the published
crates.io sources unpacked at
`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/nsh-{core,base,engine,testing,macros}-0.3.0`
(not inferred from prose), cross-checked with `https://nsh.dev/docs/*.md`,
`https://nsh.dev/elements/*.md`, `https://nsh.dev/modules/nsh-desktop.md`, and
`examples/gallery-rs/native` on `longbridge/nsh@main`.

The bootstrap, reactivity, UI, list, input, overlay, rich-content, async and
testing snippets were compiled with `cargo check` against `nsh-core`, `nsh-base`,
`nsh-engine` and `nsh-testing` 0.3.0. Compilation caught the API shapes called
out in section 10.

Warning: gallery `main` is ahead of 0.3.0 in places. Confirmed drifts:
`input().caret_color(..)` and `Viewability { item_visible_threshold, .. }` exist on
`main` but not in 0.3.0. Check any gallery snippet against the registry before
copying it.

GPUI to NSH map (one line each):

| GPUI | NSH 0.3.0 |
|---|---|
| `div()` | `view()` |
| `Entity<T>` / `Context<T>` | `stored(T)` / `Signal` / `Scope` |
| `cx.notify()` | write a signal |
| `Render` (re-runs) | `#[component]` view runs once, bindings re-run |
| `cx.spawn` | `spawn(async move { .. })` (engine thread, signals OK) |
| `cx.background_executor().spawn` | `background(fut)` (tokio thread, no signals) |
| `uniform_list` / `List` | `virtual_list(count, row)` |
| `TextInput` / `Editor` | `input()` / `nsh_base::editor()` |
| `TitleBar` / window options | `set_title_bar`, `window_drag`, `AppOptions` |
| `Theme` / `hsla` | `nsh_base::theme()` + `AdaptiveColor` / `Hsla` |
| `div().on_click` | `.on_press(move \|\| ..)` |
| `KeyBinding` | `on_key("mod+k", ..)` (surface-wide) |

## 1. App bootstrap

### Cargo.toml

```toml
[dependencies]
nsh-core = "0.3"
nsh-base = "0.3"

[target.'cfg(target_os = "macos")'.dependencies]
nsh-platform-macos = { version = "0.3", default-features = false }

[target.'cfg(target_os = "linux")'.dependencies]
nsh-platform-linux = { version = "0.3", default-features = false }

[target.'cfg(target_os = "windows")'.dependencies]
nsh-platform-windows = { version = "0.3", default-features = false }

[dev-dependencies]
nsh-engine = "0.3"
nsh-testing = "0.3"
```

- `nsh-macros` is not a direct dependency. `nsh-core` re-exports
  `component`, `Props`, `Event`, `PropEnum`, `JsObject`, `module`, `class`,
  `methods`, `native_module`, `asset`, `assets` from
  `nsh_core::element` and the prelude.
- Platform crates default to `features = ["js"]` (QuickJS). A Rust-only app sets
  `default-features = false`; the `dev` feature adds the dev server and testing.
- `nsh-platform-ios`, `-android`, `-gpui`, `-web` also publish 0.3.0. The iOS and
  Android runners are generated by `nsh run` / `nsh package`, not by `cargo run`.
- `nsh run`/`nsh package` need `nsh.json` `"rust"` and `"root"`. `cargo run` uses
  `src/main.rs` and `platform::run_app`.

### nsh.json

```json
{
  "name": "My App",
  "id": "com.example.myapp",
  "version": "1.0.0",
  "build": 1,
  "rust": "native",
  "root": "App",
  "theme": "theme.json",
  "appearance": "system",
  "icon": "icon.png"

```

Keys read by 0.3.0: `name`, `id`, `version`, `build`, `minRuntime`, `icon`,
`tailwind`, `appearance` (`"light" | "dark" | "system"`), `theme` (path or inline
`cssVars` object), `statusBar`, `capabilities`, `resolve`, `rust` (path or list of
crate paths), `web`, `root` (component path in the first crate, e.g. `App` or
`shell::Gallery`).

### src/lib.rs: root component and UI set

```rust
mod screens;

use nsh_core::prelude::*;

/// Exports the crate to TSX and creates `pub fn registry() -> Registry`.
#[native_module("my-app/native")]
fn native(registry: &mut Registry) {
    registry.register::<App>().assets(assets!());
}

#[component]
pub fn App() -> impl IntoElement {
    screens::home()
}
```

`#[native_module]` also emits `pub fn registry() -> Registry` at the crate root.
Rust-only apps still call it to get the asset list and, if TSX is added later, the
exports.

### src/main.rs: desktop run

```rust
#![cfg_attr(target_os = "windows", windows_subsystem = "windows")]

#[cfg(target_os = "macos")]

#[cfg(target_os = "linux")]
use nsh_platform_linux as platform;
#[cfg(target_os = "windows")]

        .expect("valid theme");

        platform::AppSource::Rust(
            platform::Root::of::<my_app::App>()
```

### Theme tokens from JSON

Theme files are shadcn `cssVars`:

```json
{
  "name": "My App",
  "cssVars": {
    "theme": { "radius": "12px", "font-sans": "Inter, sans-serif" },
    "light": { "primary": "#16171a", "primary-foreground": "#ffffff", "up": "#16a34a" },
    "dark":  { "primary": "#eef0f2", "primary-foreground": "#111214", "up": "#4ade80" }
  }
}
```

```rust
pub fn theme() -> Arc<Theme>                     // nsh_base, reactive read
pub fn tokens_of(json: Option<&str>) -> Result<Tokens, String>
impl Theme {
    pub fn from_json(json: &str) -> Result<Self, ThemeError>;
    pub fn into_tokens(self) -> Tokens;
    pub fn color(&self, name: &str) -> Option<AdaptiveColor>;
    pub fn number(&self, name: &str) -> Option<f32>;
    pub fn font(&self, name: &str) -> Option<Arc<str>>;

```

`Theme` fields (all `AdaptiveColor` unless noted): `background`, `foreground`,
`card`, `card_foreground`, `popover`, `popover_foreground`, `primary`,
`primary_foreground`, `secondary`, `secondary_foreground`, `muted`,
`muted_foreground`, `accent`, `accent_foreground`, `destructive`, `border`,
`input`, `ring`, `chart_1`..`chart_5`, `sidebar*`; `radius: Points`;
`font_sans: Option<SharedString>`, `font_mono: Option<SharedString>`.

Custom tokens: `theme().color("up")`, `theme().number("radius-card")`.

With `Root::tokens` unset, `nsh_core::Tokens` is empty, but `nsh_base::theme()`
fills missing names from its default (shadcn neutral). Set tokens anyway so
Tailwind classes on `app_class` and `token()` resolve the app theme.

### Signals

```rust
pub fn signal<T: PartialEq + 'static>(value: T) -> Signal<T>
pub fn signal_with<T: 'static>(value: T, equals: SignalEquals) -> Signal<T> // Never
pub fn computed<T: PartialEq + 'static>(f: impl Fn() -> T + 'static) -> Memo<T>
pub fn effect(f: impl Fn() + 'static)
pub fn cleanup(f: impl FnOnce() + 'static)
pub fn batch<R>(f: impl FnOnce() -> R) -> R
pub fn untracked<R>(f: impl FnOnce() -> R) -> R
pub fn stored<T: 'static>(value: T) -> Stored<T>
pub fn provide_context<T: Clone + 'static>(value: T)
pub fn use_context<T: Clone + 'static>() -> Option<T>
pub fn global<G: Default + 'static>() -> Signal<G>
pub fn try_global<G: Default + 'static>() -> Option<Signal<G>>
```

```rust
impl<T: 'static> Signal<T> {
    pub fn get(&self) -> T where T: Clone;                 // tracked
    pub fn with<R>(&self, f: impl FnOnce(&T) -> R) -> R;   // tracked
    pub fn get_untracked(&self) -> T where T: Clone;
    pub fn with_untracked<R>(&self, f: impl FnOnce(&T) -> R) -> R;
    pub fn try_get(&self) -> Option<T> where T: Clone;     // None after disposal
    pub fn set(&self, value: T);
    pub fn try_set(&self, value: T) -> bool;
    pub fn update(&self, f: impl FnOnce(&mut T)) where T: Clone;
    pub fn read_only(&self) -> ReadSignal<T>;
}
```

`Memo<T>` and `ReadSignal<T>` expose `get`, `with`, `get_untracked`,
`with_untracked`, `try_get`. `Stored<T>` exposes `with(|&mut T| ..)`, `replace`,
`get` (requires `Clone`).

`Signal<T>` is a `Copy` handle (a `u32` index plus generation) and is
`Send + Sync` by structure. The compiler will not stop you from moving it to a
tokio thread; using it there panics with
`no reactive runtime: signals are used on the engine thread, while components run`.
Treat every handle as engine-thread-only.

Signals live with their owner: a component, a `when` branch, an `each` row, an
effect. Disposal makes reads panic (live reads) or return `None` (`try_get`).

### Resources

```rust
pub fn resource<S, T, E, F, Fut>(
    source: impl Fn() -> Option<S> + 'static,
    fetcher: F,
) -> Resource<T, E>
where
    S: 'static, T: 'static, E: 'static,
    F: Fn(S, ResourceInfo) -> Fut + 'static,
    Fut: Future<Output = Result<T, E>> + 'static;

pub fn resource_with_value<S, T, E, F, Fut>(value: T, source: ..., fetcher: F) -> Resource<T, E>

impl<T, E> Resource<T, E> {
    pub fn get(&self) -> Option<T> where T: Clone;
    pub fn error(&self) -> Option<E> where E: Clone;
    pub fn state(&self) -> ResourceState;   // Unresolved | Pending | Ready | Refreshing | Errored
    pub fn loading(&self) -> bool;
    pub fn refetch(&self);
    pub fn mutate(&self, value: T);
}
```

The fetcher is a plain (not `Send`) future; a new load or owner disposal cancels
the running one.

### `#[component]`

```rust
#[derive(Debug, Clone, PartialEq, Props)]
pub struct StepperProps {
    /// The starting value.
    pub value: Prop<i32>,
    /// Largest allowed.
    #[prop(default = 10)]
    pub max: Prop<i32>,
    /// The label.
    pub label: Prop<Option<SharedString>>,
}

#[derive(Debug, Clone, PartialEq, Event)]
pub enum StepperEvent {
    /// The value changed.
    #[args(value)]
    Change(i32),
}

/// A number with minus and plus buttons.
#[component]
pub fn Stepper(props: StepperProps, cx: Scope<StepperEvent>) -> impl IntoElement {
    let value = signal(props.value.get_untracked());
    view()
        .flex_row()
        .gap_2()
        .child(
            text(move || format!("{}", value.get()))
                .text_size(px(16.0)),
        )
        .child(
            nsh_base::button()
                .on_press(move || {
                    value.update(|v| *v += 1);
                    cx.emit(StepperEvent::Change(value.get_untracked()));
                })
                .child(text("+")),
        )
}
```

Generated API:

- `stepper()` returns `StepperElement` (a `ComponentElement<Stepper>`).
- One setter per prop, named after the field: `.value(..)`, `.max(..)`,
  `.label(..)`. Setters take a value, `Signal`/`Memo`/`ReadSignal`, `Prop`,
  `Reactive`, or a closure returning the value (`impl IntoProp<T, M>`).
- One listener per event variant, snake case: `.on_change(move |v: &i32| ..)`.
- A component with no `Scope` parameter has `Event = NoEvent`; with no props
  struct it has `Props = ()`. `#[component] pub fn App() -> impl IntoElement`
  is valid.
- `.child(..)` fills the component's `Children` (lazy). `Option<Slot>` props get
  a setter that takes `impl IntoElement`: `.trigger(button().child(text("Open")))`.
- `Prop<Children>` has no setter; use `.child(..)` / `.children(..)`.

Inside the view:

```rust
cx.emit(StepperEvent::Change(3));          // to JS or the parent Rust component
cx.methods(api);                            // expose `Api` methods through a ref
let insets: EdgeInsets = cx.insets();      // safe area or screen/modal insets
```

`#[methods] impl StepperApi { pub fn set_value(&self, ..) }` plus
`#[component(methods = StepperApi)]` makes the methods callable from JS and from
`ComponentRef::api::<StepperApi>()`.

### Control flow and children

```rust
pub fn dynamic<E: IntoElements>(f: impl Fn() -> E + 'static) -> AnyElement
pub fn when<E: IntoElements>(condition: impl IntoReactive<bool>, then: impl Fn() -> E + 'static) -> If
impl If { pub fn otherwise<E: IntoElements>(self, f: impl Fn() -> E + 'static) -> Self }
pub fn each<T, K, E>(
    items: impl IntoReactive<Vec<T>>,
    key: impl Fn(&T) -> K + 'static,
    row: impl Fn(ReadSignal<T>, ReadSignal<usize>) -> E + 'static,
) -> AnyElement
where T: Clone + PartialEq + 'static, K: Hash + Eq + Clone + 'static, E: IntoElements

pub fn catch_error<E: IntoElements, F: IntoElements>(
    view: impl Fn() -> E + 'static,
    fallback: impl Fn(ComponentError, Reset) -> F + 'static,
) -> AnyElement
```

```rust
view()
    .child(when(open, move || panel()).otherwise(move || placeholder()))
    .child(each(
        move || rows.with(|r| r.clone()),
        |row: &Row| row.id,
        move |row, index| text(move || format!("{}: {}", index.get(), row.get().title)),
    ))
```

`each` keys rows; a key that stays keeps its nodes and bindings, and only its
`item`/`index` signals change. `when` remakes a branch only when the condition
flips. `dynamic` remakes whenever anything it reads changes; prefer `when`/`each`.

`.when(cond, |v| ..)` and `.when_some(opt, |v, x| ..)` on any builder decide
once, at element construction. `.style_when(reactive_cond, |s| ..)` switches
styles while the app runs.

`Owner` / `create_root` exist for code outside a component; do not create effects
in event handlers, timers, or tasks unless you keep the returned `Owner`.

Row identity and recycling:

- The row closure is called once per cell, not once per item. Cells are reused;
  `at.index()` changes under them.
- Read the index inside bindings: `text(move || rows[at.index()].title.clone())`.
  A value copied at the top of the row function sticks to the cell's first item.
- Per-item state must live in the app's data keyed by id, not in signals created
  inside the row function (those travel with the cell).
- `keys(..)` keeps cells and sizes when rows are inserted or removed before the
  end. Without it, only appends are cheap.
- The list must get a bounded size from its parent (`.flex_1()` or a height).

## 6. Overlays

### Core overlay

```rust
overlay()                                   // position: fixed in its root view
    .anchor(&trigger_ref)                   // place against an element
    .anchor_content(&trigger_ref)           // place against what it draws
    .anchor_point(point(px(x), px(y)))      // pointer position
    .anchor_bounds(bounds)                  // e.g. an input caret
    .placement(Placement::Bottom)           // Top | Bottom | Left | Right
    .align(Align::Start)                    // Start | Center | End
    .offset(px(6.0))
    .margin(px(8.0))                        // keep off the safe area edges
    .on_press_outside(move |_: &Point<Points>| close())
    .on_cancel(move || close())             // Escape / Android back
    .hint(Duration::from_millis(500))       // tooltip behavior
    .hint_open(move || Some(open.get()))
    .on_hint_show(..) .on_hint_hide(..)
    .on_position(|&OverlayPosition| ..)
```

Placement rules: without an anchor, fixed box of the root view (`.absolute()
.inset_0()` covers it). With an anchor, the requested side, flipped to the
opposite side when only that one fits, aligned along the side, kept inside the
root view's safe area, and following the anchor as it moves.

Listener annotation: `on_press_outside(move |_| ..)` fails with a
higher-ranked lifetime error in 0.3.0. Annotate the argument:
`move |_: &Point<Points>| ..`.

Overlays live on top of the root view they are in (the surface, or the dialog
around them), outside the parent's layout and clipping, but keep the parent's
reactive context, events and lifetime. Close by removing them from the view
(`when(open, ..)`).

### Table and DataTable

`table()` is a static semantic table, no data model: `table().child(table_header()
.child(table_row().child(table_head().child(text("Name")))))`, then
`table_body()`, `table_row()`, `table_cell()`, `table_footer()`,
`table_caption()`. Use it for small, fully composed tables.

`data_table()` is the virtualized table. Two 0.3.0 Rust limitations:

- `DataTableColumn` is `#[non_exhaustive]` and has no constructor. Build one with
  `Default` and field assignment (`let mut c = DataTableColumn::default();
  c.key = "name".into();`), not a struct literal.
- `DataTableRows` has no public constructor. It exposes only `Default`, `len`,
  `is_empty` and `JsValue::from_js`; `from_arrays` / `from_objects` are
  `#[cfg(test)]`. A Rust component can set columns, selection and events, but
  cannot feed rows. For a Rust port use `table()` for small tables, or a grid
  built with `virtual_list(count, ..).columns(n)`.

```rust

name.title = Some("Name".into());
name.width = Some(px(240.0));

name.sortable = true;

    .columns(vec![name])
    .row_count(Some(total))
    .data_start(0)
    .row_height(px(32.0))
    .selection(selection)
    .render_cell(move |cell: &DataTableCell| ..)
    .empty(slot)
    .on_selection_change(move |selection: &Option<DataTableSelection>| ..)
    .on_sort_change(..)
    .on_load_more(..)
```

## 8. Async and threads

The engine thread runs app code, the reactive graph, rendering, text and layout;
the main thread only applies `MountBatch`, draws text, runs native animations and
collects gestures. The main thread never waits for app code.

```rust
pub fn spawn<T: 'static>(future: impl Future<Output = T> + 'static) -> Spawned<T>
pub fn background<F>(future: F) -> tokio::task::JoinHandle<F::Output>
    where F: Future + Send + 'static, F::Output: Send + 'static;
pub fn blocking<R: Send + 'static>(f: impl FnOnce() -> R + Send + 'static)
    -> tokio::task::JoinHandle<R>;

pub fn set_timeout(delay: Duration, f: impl FnOnce() + 'static) -> Spawned<()>
pub fn set_interval(period: Duration, f: impl Fn() + 'static) -> Spawned<()>
pub fn timer(delay: Duration) -> Delay
pub fn timer_until(at: Instant) -> Delay
pub fn next_frame() -> Answer<Instant>
pub fn request_animation_frame(f: impl FnOnce(Instant) + 'static) -> Spawned<()>
pub fn fetch(request: impl Into<HttpRequest>) -> Fetch
    // Fetch: Future<Output = Result<HttpResponse, String>>
```

- `spawn` polls the future on the engine thread, inside a tokio runtime context
  (`Handle::enter`). Signals may be written directly; the future need not be
  `Send`. Tasks are canceled when their owner is disposed or `Spawned::cancel`
  is called. `Spawned<T>` is itself a `Future`.
- `background` runs on the tokio runtime's worker threads. It requires `Send`,
  and it must not touch signals, `ElementRef`, `Answer`, or any other `Rc`-based
  handle. Those accesses panic at runtime, not compile time.
- `blocking` is `tokio::task::spawn_blocking`, with the same rule.
- Timers used in `spawn` are the core's own (fired by the engine loop); awaited
  outside an engine they fall back to tokio.

### Bridging an existing tokio controller

The controller's events on a `tokio::sync::mpsc::Receiver` can be consumed by an
engine-thread task directly, because `spawn` polls inside a tokio context:

```rust
struct Controller { /* tokio handles, state */ }

#[component]
pub fn App(controller: ControllerHandle) -> impl IntoElement {
    let rows = signal(Vec::<Row>::new());
    let rx = controller.take_events();     // tokio::sync::mpsc::Receiver<Event>
    spawn(async move {
        while let Some(event) = rx.recv().await {
            match event {
                Event::Rows(v) => rows.set(v),
                Event::Status(s) => status.set(s),
            }
        }
    });
    // ..
}
```

- `tokio::sync::mpsc::Receiver::recv` needs no runtime of its own; the waker
  wakes the engine. A `tokio::sync::mpsc::UnboundedSender` may be cloned and
  used from any thread.
- If the controller must run on its own runtime and cannot be polled on the
  engine thread, run it with `background(async move { controller.run().await })`
  and have it send into a second `tokio::sync::mpsc` channel; drain that channel
  in an engine `spawn` as above.
- Keep the controller itself in `stored(Controller::default())` and call methods
  with `controller.with(|c| c.command(..))`. `Stored` is the `Entity`-like
  non-reactive handle.
- Never call `Signal::set`, `Signal::get`, `ElementRef::*`, `Answer` polling, or
  `nsh_base` component APIs from a `background` task.

`Answer<T>` (from `measure`, `fetch`, `alert_dialog`, `open_url`, `next_frame`)
is a `Future` backed by `Rc<RefCell<..>>`; await it inside `spawn`.

`nsh_core::time` gives `now()`, `unix_ms()`, and `Instant` (std off wasm).
`Storage::get_item/set_item/remove_item` are synchronous and engine-thread only.

## 10. Known gaps and gotchas

Confirmed against 0.3.0 sources.

1. **Application menu and most window commands are JS-only.** Rust has
   `set_title_bar`, `title_bar`, `close_window`, `window_drag`. `setTitle`,
   `setMenuBar`, `minimize`, `toggleMaximize`, `toggleFullScreen`, `setFrame`,
   `setLevel`, `orderFront`, `setApplicationMenu` exist only in `nsh/desktop`
   (`Window.*`, `Menu.popup`) for TSX. `run_app` installs a default macOS menu.
   A port that needs a custom app menu or runtime window control must either use
   an in-window `Menu`/`ContextMenu`, embed `AppView` in a host that controls the
   `NSWindow`/HWND/GTK window, or add TSX. This is the largest porting blocker.
2. **No per-element key events.** `on_key`/`on_key_with` bind surface-wide.
   Inputs have `on_key_press`; the Editor has its own keys. A GPUI view with
   scoped keyboard handling needs a focus signal plus surface bindings with
   `When::NotEditing`/`Always`, or a custom native component.
3. **Signals are engine-thread-only by contract, not by type.** `Signal<T>`,
   `Memo<T>`, `ReadSignal<T>`, `Prop<T>` and `Stored<T>` are auto-`Send` because
   they hold a `u32` handle and `PhantomData<fn() -> T>`. Moving one to a tokio
   thread compiles; using it panics. Use `spawn` for signal writes, `background`
   only for `Send` work that sends through a channel.
4. **`spawn` requires `'static`, not `Send`; `background` requires `Send`.** Do
   not try to move `ElementRef`, `Answer`, `Resource` or `Rc` app state into
   `background`.
5. **No multi-window API in components.** One `AppView` is one window/engine.
   Multiple windows require the embedding host to create multiple `AppView`s.
6. **`nsh_base` components are unstyled.** `Button`, `Input`, `Menu`, `Toast`,
   `Tabs`, `ResizablePanel`, `DockArea`, `Table`, `DataTable`, `Editor`,
   `TextView`, `DiffView` provide behavior, accessibility and layout only. Every
   color, radius, padding and font comes from the app.
7. **Toast has no imperative helper.** `ToastManager` + `ToastStack` + `Toast`
   must be wired manually; there is no `toast("Copied")`.
8. **`Root::of::<C>()` needs `C::Props: Default`.** Use
   `Root::new::<C>(|| props)` otherwise.
9. **`signal` needs `T: PartialEq`; `get`/`update` need `T: Clone`.** `update`
   notifies on every call; `set` compares with `PartialEq`.
10. **`each` needs `T: Clone + PartialEq`, `K: Hash + Eq + Clone`.** Keys are
    hashed, not kept by identity.
11. **List rows are recycled.** A value read once at the top of the row closure
    belongs to the cell, not the item. Read `at.index()` in bindings; keep
    per-item state in data keyed by id.
12. **Lists and scroll views need a bounded size** from their parent
    (`.flex_1()` or explicit height), as in GPUI.
13. **Refs are inert before mount and after disposal.** `measure()` is async and
    must be awaited in `spawn`. Commands sent to an unmounted ref do nothing.
14. **`on_key` panics** on invalid keystrokes and platform-reserved keys
    (Cmd+Q/H/M, Ctrl+Cmd+F, Ctrl+Q, Alt+F4, F11). Validate shortcut strings at
    startup or wrap in a test.
15. **Layout defaults differ from the web:** column direction, no shrink,
    min size 0. A `flex: 1` child in a row shrinks and wraps.
16. **Strings outside `text(..)` do not render.** A `view().child("hi")` is a
    silent no-op visually.
17. **`Slot` props are set with an element**, not a closure:
    `.trigger(button().child(text("Open")))`. `Children` props are filled with
    `.child(..)`, not a setter.
18. **`nsh.json` theme only reaches a Rust root through the CLI runner.** With
    `cargo run` you must pass `Root::tokens(Theme::from_json(..)?.into_tokens())`
    yourself. Without tokens, `nsh_base::theme()` still fills defaults, but
    Tailwind classes on `app_class` resolve against empty tokens.
19. **Platform crates default to `js`** (QuickJS). For a Rust-only app set
    `default-features = false`; `nsh run`/`nsh package` already build without
    QuickJS.
20. **Gallery `main` drifts from 0.3.0.** Confirmed: `input().caret_color(..)`
    and `Viewability { item_visible_threshold, .. }` are not in 0.3.0. The docs
    also still show `nsh-engine = "0.1"` / `nsh-testing = "0.1"` in examples;
    the published version is 0.3.0.
21. **No generic drag-and-drop framework.** File drops (`on_file_drop`),
    pan gestures (`on_pan_start`/`on_pan_end`, `pan_values`) and the Dock's own
    tab dragging exist; app-level drag between arbitrary views must be built
    from those.
22. **`Window` title is fixed at startup** from `AppOptions.title` in Rust.
23. **`alert_dialog().show()` returns `Answer<Result<Option<SharedString>, String>>`**
    and must be awaited in a task; it is not a component.
24. **`native(name)` requires host registration.** macOS:
    `AppView::register_component(name, factory)` or
    `AppOptions.components`; the `NativeComponent` trait has `view()`,
    `set_prop(name, Option<&JsonValue>)`, `command(name, args)`,
    `set_animated_number`, `set_animated_color`. An unregistered name renders an
    empty view and logs once.
25. **`DataTableRows` is not constructible from Rust in 0.3.0.** The type has
    only `Default`, `len`, `is_empty` and `JsValue::from_js`; the array/object
    builders are test-only. `DataTable` is effectively TSX-only for data. Use
    `table()` or a `virtual_list` grid in Rust, or wait for a newer release.
    `DataTableColumn` is `#[non_exhaustive]`; build it with `Default` plus field
    assignment.
26. **`input()` is not in `nsh_core::prelude`.** Import
    `nsh_core::element::input` or use `nsh_base::input`. The prelude also omits
    the doc-hidden `stack`/`screen`/`modal`; use `nav_stack`, `nav_page`,
    `dialog`.
27. **Multi-field event listeners receive the whole event enum.** For
    `#[args(open, reason)] OpenChange(bool, OpenChangeReason)`, the method is
    `.on_open_change(|e: &PopoverEvent| ..)`, not a two-argument closure. A
    one-field variant gives the field, a unit variant gives `()`.
28. **Some listener closures need explicit argument types.**
    `.on_press_outside(move |_| ..)` fails with a higher-ranked lifetime error;
    write `move |_: &Point<Points>| ..`. The same pattern applies to other
    `Fn(&T)` listeners where inference has no anchor.
29. **`Style::from_decls` takes `impl IntoIterator<Item = StyleDecl>`.** A
    `Style` built from typed styles is also accepted by setters that take
    `impl IntoReactive<Style>`, and `style(|s| ..)` on a component prop takes a
    closure over `StyleRefinement`.
