# 2026-07-25

## Subagent session_id 缺失 — 影响面梳理

用户问：当前的 subagent 没有 session id，会有什么问题吗？

定位：`crates/tact/src/tool/subagent.rs:33-46` 通过 `Agent::new(...)` 直接构造子 agent，没有调用 `with_session()`。所以：

- `runtime.session_id = None`
- `runtime.session_store = None`
- `runtime.client.set_user_id(&session_id)` 也从未被调用（DeepSeek 用来做 KV cache 隔离）

### 后果

由于 `Agent` 的所有持久化路径都先 early-return：

| 路径 | 位置 | 影响 |
|------|------|------|
| `persist_message` | `agent/mod.rs:266-282` | 子 agent 整个对话**不落库**，结束后只剩返回给父 agent 的那段 summary |
| `persist_llm_call` | `agent/mod.rs:302-328` | 子 agent 的 **token 用量不记账**——成本统计、API request_body 调试都拿不到 |
| `persist_tool_schedule` | `agent/mod.rs:333-346` | 子 agent 的工具调度策略不归档 |
| `replace_persisted_context` | `agent/mod.rs:284-298` | 即便子 agent 触发 compaction，compaction 后的消息也没人接住 |
| `set_user_id` 没调 | `tact_llm/src/inject.rs` 注释明确「for KV cache isolation」 | DeepSeek 的 prefix cache 没法按 session 隔离——子 agent 和父 agent 的请求会互相污染 cache，或者完全失去 cache 命中 |

### 用户可见的副作用

- TUI 底栏 token 计数不包含子 agent 的消耗
- `select.rs:80` 的 "查看最近一次 LLM 请求体" 在跳转到子 agent 那次调用时拿不到内容
- 子 agent 中途崩溃无法恢复（没有持久化消息可恢复）
- 子 agent 的对话历史在 TUI 里查不到

### 是否是 bug？

- 若是「subagent 一次性、只用 summary 回到父 agent」的语义，丢掉历史是**有意的**——但 token 用量、request_body、tool-schedule 这些遥测数据通常不希望丢。
- 更干净的做法：让 subagent 也走 `with_session()`，派生一个 `parent_id:sub-<uuid>` 之类的 session id，既能完整记账，又能在 DB 里和父 session 关联。
